Todos comparten una filosofía: el siguiente valor se expresa como combinación lineal del pasado (de la propia serie y/o de los errores) y opcionalmente otras variables exógenas.

AR(p) — autoregresivo

\[ y_t = c + \phi_1 y_{t-1} + \phi_2 y_{t-2} + \cdots + \phi_p y_{t-p} + \varepsilon_t \]

  • \(\phi_i\) son los coeficientes autorregresivos.
  • \(\varepsilon_t \sim \mathcal{N}(0, \sigma^2)\) ruido blanco.
  • Identificación: PACF se corta en lag \(p\).

AR(2) — PACF que se corta en lag 2

from statsmodels.tsa.arima_process import ArmaProcess
from statsmodels.graphics.tsaplots import plot_pacf
np.random.seed(0)
ar2 = ArmaProcess([1, -0.8, 0.2]).generate_sample(400)
fig, ax = plt.subplots(figsize=(8, 2.4))
plot_pacf(ar2, lags=15, ax=ax, method="ywm", color="#1f6f8b")
ax.set_title(""); ax.set_xlabel("Lag"); plt.tight_layout()

MA(q) — media móvil

\[ y_t = c + \varepsilon_t + \theta_1 \varepsilon_{t-1} + \cdots + \theta_q \varepsilon_{t-q} \]

  • “Shock” reciente que se propaga \(q\) pasos.
  • Identificación: ACF se corta en lag \(q\).

ARMA(p,q) = mezcla de los dos: \(y_t\) depende de su pasado y de errores pasados.

ARMA sólo funciona si la serie es estacionaria. Si no lo es → ARIMA.

MA(1) — ACF que se corta en lag 1

Regla práctica: AR(p) → PACF se corta en \(p\), ACF decae; MA(q) → ACF se corta en \(q\), PACF decae.

ARIMA(p, d, q)

\[ \nabla^d y_t \sim \mathrm{ARMA}(p, q) \]

donde \(\nabla y_t = y_t - y_{t-1}\) es la diferencia primera.

  • \(d\): número de diferenciaciones para hacer estacionaria la serie.
    • \(d = 0\) → ya estacionaria (rara vez en hidrología).
    • \(d = 1\) → tendencia lineal eliminada.
    • \(d = 2\) → curvaturas. Casi nunca necesario.

Elegir \(d\): tests ADF/KPSS sobre la serie y sus diferencias. Si KPSS sigue rechazando con \(d=1\), prueba \(d=2\).

ARIMA — diferenciar para estabilizar

Misma serie tras np.diff: media y varianza ya no se mueven con el tiempo → ARMA aplicable.

SARIMA(p,d,q)(P,D,Q,s)

Extiende ARIMA con estacionalidad de periodo \(s\):

  • \((p, d, q)\): parte regular.
  • \((P, D, Q)\): parte estacional (lags múltiplos de \(s\)).
  • \(s\): período (12 si mensual con ciclo anual, 7 si diario con ciclo semanal, 24 si horario con ciclo diario).

SARIMAX — covariables exógenas

\[ y_t = \mathrm{SARIMA}(p,d,q)(P,D,Q,s) + \beta_1 x_{1,t} + \cdots + \beta_k x_{k,t} \]

En hidrología la covariable canónica es la lluvia acumulada retardada (la respuesta del caudal es plurimensual: agua de varios meses se va liberando del suelo / acuíferos):

from statsmodels.tsa.statespace.sarimax import SARIMAX

endog = CAUDAL_M.asfreq("MS").dropna()
exog = LLUVIA_M.asfreq("MS").rolling(3).sum().shift(1).reindex(endog.index)
mask = exog.notna()
modelo = SARIMAX(endog[mask], exog=exog[mask],
                 order=(1,0,0), seasonal_order=(0,1,1,12)).fit(disp=False)
nombre_exog = modelo.model.exog_names[0]
print(f"AIC = {modelo.aic:.1f}   coef lluvia 3m ({nombre_exog}) = {modelo.params[nombre_exog]:.4f}")
AIC = 835.8   coef lluvia 3m (lluvia_era5_37.163_-3.493) = 0.0021

Órdenes: caudal ya estacionario en nivel (ADF rechaza) → \(d=0\); estacionalidad anual marcada → \(D=1\) con \(\mathrm{SMA}(1)\). Coef positivo → más lluvia acumulada → más caudal.

Box-Jenkins — la receta clásica

Cuatro pasos iterativos:

  1. Identificación — STL + ADF/KPSS para elegir \(d\), \(D\); ACF/PACF para órdenes iniciales.
  2. Estimación — ajustar por máxima verosimilitud.
  3. Diagnóstico — residuos = ruido blanco? Ljung-Box, Q-Q plot, ACF de residuos.
  4. Pronóstico — si pasa el diagnóstico.

Si el diagnóstico falla → volver al paso 1 con otros órdenes.

Diagnóstico de residuos

Diagnóstico — qué comprobar

  • Residuos sin patrón (top-left).
  • Histograma ~ normal y Q-Q lineal.
  • ACF de residuos plana (sin lags significativos).

Verosimilitud (likelihood) en 60 segundos

Dado un modelo con parámetros \(\theta\) y datos \(y_1, \ldots, y_n\), la verosimilitud es:

\[ \mathcal{L}(\theta) = p(y_1, \ldots, y_n \mid \theta) \]

la probabilidad de observar esos datos si el modelo es cierto.

En ARIMA/ETS con errores gaussianos asumimos \(\varepsilon_t = y_t - \hat y_t \sim \mathcal{N}(0, \sigma^2)\), así que

\[ \ln \mathcal{L} = -\frac{n}{2} \ln(2\pi\sigma^2) \;-\; \frac{1}{2\sigma^2}\sum_t \varepsilon_t^2 \]

(maximizar \(\ln \mathcal{L}\) equivale a minimizar la suma de cuadrados de los residuos cuando \(\sigma\) es libre).

Selección de modelo — AIC, BIC, AICc

Añadir parámetros siempre aumenta \(\ln \mathcal{L}\) (sobre los datos observados). Hay que penalizar complejidad ⇒ AIC/BIC.

Penalizan el ajuste según los parámetros usados. Cuanto más bajo, mejor:

\[ \mathrm{AIC} = -2 \ln \mathcal{L} + 2 k, \qquad \mathrm{BIC} = -2 \ln \mathcal{L} + k \ln n \]

\(k\) = nº de parámetros del modelo, \(n\) = tamaño muestral.

  • AIC premia ajuste; tolera modelos más grandes.
  • BIC penaliza más; favorece modelos parsimoniosos.
  • AICc = AIC corregido para \(n\) pequeño: \(\mathrm{AIC} + \dfrac{2k(k+1)}{n-k-1}\).

Suavizado exponencial (ETS)

ETS — la otra gran familia

Idea central: descomponer la serie en hasta tres componentes — nivel, tendencia y estacionalidad — y actualizar cada una recursivamente con una media ponderada que da más peso a lo reciente.

Nomenclatura ETS = Error, Trend, Seasonal. Cada componente puede ser Aditiva, Multiplicativa o Ninguna.

Notación: ETS(A,A,A), ETS(A,Ad,A), ETS(M,A,M)… → 19 combinaciones posibles.

Casos clásicos:

  • ETS(A,N,N) = Simple Exponential Smoothing (sólo nivel).
  • ETS(A,A,N) = Holt (+ tendencia lineal).
  • ETS(A,A,A) = Holt-Winters aditivo (+ estacionalidad).

SES — la operación básica

El suavizado exponencial simple actualiza el pronóstico como media ponderada entre el último valor observado y el pronóstico anterior:

\[ \hat{y}_{t+1} = \alpha\, y_t + (1-\alpha)\, \hat{y}_t, \qquad \alpha \in (0, 1) \]

Desarrollando la recursión hacia atrás:

\[ \hat{y}_{t+1} = \alpha y_t + \alpha(1-\alpha) y_{t-1} + \alpha(1-\alpha)^2 y_{t-2} + \cdots \]

los pesos \(\alpha(1-\alpha)^k\) decaen exponencialmente con la antigüedad → de ahí el nombre de la familia.

  • \(\alpha\) alto (≈ 1) → reactivo, sigue de cerca al último valor.
  • \(\alpha\) bajo (≈ 0) → muy suavizado, lento a reaccionar.

De SES a Holt-Winters

Cada componente añade una ecuación de actualización con su propio parámetro de suavizado:

Modelo Componentes Parámetros
SES — ETS(A,N,N) nivel \(\ell_t\) \(\alpha\)
Holt — ETS(A,A,N) + tendencia \(b_t\) \(\alpha, \beta\)
Holt-Winters — ETS(A,A,A) + estacional \(s_t\) (período \(m\)) \(\alpha, \beta, \gamma\)

Pronóstico Holt-Winters a horizonte \(h\):

\[ \hat{y}_{t+h} = \underbrace{\ell_t}_{\text{nivel}} + \underbrace{h\, b_t}_{\text{tendencia}} + \underbrace{s_{t+h-m}}_{\text{estacional}} \]

los tres estados \(\ell_t, b_t, s_t\) se actualizan recursivamente cada paso con \(\alpha, \beta, \gamma\) respectivamente.

Holt-Winters — ecuaciones de actualización

Cada nueva observación \(y_t\) actualiza los tres estados. Cada ecuación tiene la misma forma SES: λ × (estimación reciente del componente) + (1-λ) × (valor previo).

Nivel — quita la estacionalidad de \(y_t\) y promedia con el nivel proyectado:

\[ \ell_t = \alpha\,(y_t - s_{t-m}) + (1-\alpha)(\ell_{t-1} + b_{t-1}) \]

Tendencia — cambio reciente del nivel, suavizado:

\[ b_t = \beta\,(\ell_t - \ell_{t-1}) + (1-\beta)\, b_{t-1} \]

Holt-Winters — leyendo las ecuaciones

Estacional — desviación residual respecto al nivel + tendencia, suavizada con el patrón del ciclo anterior:

\[ s_t = \gamma\,(y_t - \ell_{t-1} - b_{t-1}) + (1-\gamma)\, s_{t-m} \]

  • \(y_t - s_{t-m}\) → “desestacionaliza” la observación antes de incorporarla al nivel.
  • \(\ell_t - \ell_{t-1}\) → estimación cruda de la pendiente; \(\beta\) controla cuánto te fías.
  • \(y_t - \ell_{t-1} - b_{t-1}\) → lo que sobra tras restar nivel y tendencia — eso debería ser puro patrón estacional.

Holt-Winters en una línea

from statsmodels.tsa.holtwinters import ExponentialSmoothing
ets = ExponentialSmoothing(CAUDAL_M.dropna(), trend="add",
                           seasonal="add", seasonal_periods=12).fit()
print(f"α (nivel) = {ets.params['smoothing_level']:.3f}")
print(f"β (tendencia) = {ets.params['smoothing_trend']:.3f}")
print(f"γ (estacional) = {ets.params['smoothing_seasonal']:.3f}")

β (tendencia) = 0.000
γ (estacional) = 0.000

Prophet

Prophet — modelo aditivo de Meta

Publicado por Meta en 2017 para pronóstico de negocio. Backend bayesiano (STAN); diseñado para que los defaults funcionen sin experto.

\[ y(t) = g(t) + s(t) + h(t) + \sum_j \beta_j\, x_j(t) + \varepsilon_t \]

  • \(g(t)\): tendencia por tramos con changepoints.
  • \(s(t)\): estacionalidades múltiples vía Fourier (anual/semanal/diaria/custom).
  • \(h(t)\): festivos y eventos especiales.
  • \(\beta_j x_j(t)\): regresores exógenos (add_regressor).
  • \(\varepsilon_t\): ruido gaussiano.

Prophet — hiperparámetros

Prophet no admite AIC/BIC (priors variables → verosimilitud no comparable). Vía estándar: rolling-origin CV + grid search con prophet.diagnostics.cross_validation + performance_metrics.

Las palancas, en orden de impacto:

  • changepoint_prior_scale (0.05) — flexibilidad de la tendencia. Bajo → casi lineal; alto → se adapta agresivamente. El más impactante.
  • seasonality_prior_scale (10) — amplitud estacional. Bajo → suprimida; alto → patrones marcados.
  • seasonality_mode (additive) — usar multiplicative cuando la amplitud crece con el nivel (ventas).
  • yearly_seasonality (auto, ~10) — orden Fourier. Subir afina picos pero confunde tendencia ↔︎ estacionalidad.
  • add_regressor(prior_scale=) (10) — sensibilidad de regresores exógenos. Bajar para regularizar.

Tunear suele significar grid log-escala sobre los dos primeros; el resto se deja por defecto salvo síntoma concreto.

Prophet vs ETS

Los dos descomponen la serie en nivel + tendencia + estacionalidad. Lo que cambia es cómo se estima cada componente:

ETS Prophet
Componentes se estiman… recursivamente, estado evoluciona paso a paso como curvas paramétricas globales de \(t\)
Tendencia \(\ell_t, b_t\) se actualizan con \(\alpha, \beta\) función por tramos con changepoints
Estacionalidad un solo período \(m\) (índices \(s_t\)) múltiples períodos vía series de Fourier
Festivos / eventos no nativos término \(h(t)\) explícito
Cambio de régimen la recursión “olvida” lo viejo changepoints detectados o fijados
Datos faltantes requiere rejilla regular tolerados

Mnemonic: ETS es local y adaptativo (lo reciente pesa más, vía recursión); Prophet es global y declarativo (ajustas una curva sobre todo el rango).

Prophet vs SARIMAX — dos filosofías

SARIMAX Prophet
Filosofía \(y_t\) depende de \(y_{t-1}, \ldots\) + errores pasados \(y(t)\) = tendencia + ciclos + festivos
Modelo Estocástico autoregresivo Curva determinista + ruido
Estacionariedad Requerida (vía \(d\)) No requerida
Datos irregulares / NaN Necesita rejilla Tolerado nativamente
Cambios de régimen Refit manual Changepoints automáticos
Multi-estacionalidad Una sola \(s\) Anual + semanal + diaria + custom

Pastas — piezometría con respuesta a impulsos

El problema de la piezometría

Caudales: tenemos densidad temporal alta (diario o sub-horario), tendencia mínima, estacionalidad clara → modelos clásicos funcionan.

Piezometría:

  • Muestreo irregular (meses entre mediciones).
  • Series de años a décadas.
  • Influida por lluvia, bombeo, temperatura, mareas (en costa)…

ARIMA aquí no encaja. La filosofía cambia: en lugar de modelar \(h_t\) vs su pasado, modelamos cómo responde a estímulos (lluvia, bombeo).

Marco matemático: Transfer Function Noise (TFN)

Pastas implementa un modelo TFN (Box & Jenkins, 1976; von Asmuth et al., 2002), una familia distinta de ARIMA puro:

\[ h(t) = d + \sum_{i=1}^{N} (\theta_i * s_i)(t) + n(t) \]

TFN — términos del modelo

  • \(s_i(t)\): estímulos o stresses (lluvia, bombeo, ET₀…).
  • \(\theta_i\): función de respuesta a impulso (IRF) paramétrica (p. ej. Gamma, 2–3 params).
  • \(*\): convolución — captura cómo y cuándo cada estímulo se propaga al nivel.
  • \(n(t)\): ruido residual, AR(1) en tiempo continuo → tolera muestreo irregular.
  • \(d\): nivel base.

TFN vs SARIMAX — ¿por qué no usar SARIMAX?

Ambos admiten exógenas, pero la forma de la respuesta cambia radicalmente:

SARIMAX TFN (Pastas)
Cómo entra el estímulo Coeficiente \(\beta x_t\) (o \(\sum_k \beta_k x_{t-k}\) a mano) Convolución con IRF paramétrica
Forma de la respuesta Plana / impuesta por el usuario Aprendida: escala, retardo al pico, decaimiento
Nº params por estímulo \(1\) (o \(k\) si añades \(k\) lags) \(2\)–\(3\) (Gamma: gain, shape, scale)
Muestreo irregular Necesita rejilla regular Nativo (AR(1) continuo)
Interpretación física Limitada Tiempo al pico, memoria del acuífero

Regla: caudal denso con estacionalidad fuerte → SARIMAX. Piezometría sparsa, multi-década, respuesta diferida → TFN/Pastas.

En la práctica · poniendo el modelo a predecir

Forecasting en producción · la API

API de statsmodels — la usan ARIMA, SARIMA, SARIMAX y ETS/Holt-Winters (y VAR, UnobservedComponents). Todo Results ajustado expone:

# Predicción puntual h pasos al futuro
preds = modelo.forecast(steps=h)

# Versión con incertidumbre
fc   = modelo.get_forecast(steps=h)
mu   = fc.predicted_mean
ic95 = fc.conf_int(alpha=0.05)

Las otras librerías usan su propia API:

  • Prophet: m.make_future_dataframe(periods=h) + m.predict().
  • Pastas: ml.simulate(tmax="2030-12-31").

Regla: las bandas crecen con \(h\) — un pronóstico a 24 meses es mucho menos certero que uno a 1 mes. Comunica la incertidumbre, no solo la media.

Mantener el modelo al día

Los datos nuevos llegan. Tres niveles según qué se re-toca: hiperparámetros (órdenes \(p, d, q, \ldots\)) y parámetros (\(\phi, \theta, \sigma^2\)).

Acción Hiperparámetros Parámetros Coste Cadencia
.append(nuevos) fijos fijos Bajo Cada paso
Refit completo fijos re-estimados con la serie ampliada Alto Semana / mes
Re-selección re-elegidos vía auto_arima / AIC re-estimados Muy alto Trimestre / año

Receta:

  • append cada paso
  • refit cada \(N\) pasos
  • re-selección sólo si los datos cambian sustancialmente

Mapa final

¿Qué modelo usar y cuándo?

Situación Modelo recomendado
Caudal/nivel con estacionalidad clara, sin covariables ETS (Holt-Winters)
Caudal con lluvia como input SARIMAX
Múltiples estacionalidades, holidays, datos a trozos Prophet
Piezometría irregular con lluvia/bombeo Pastas
Necesitas más capacidad → eventos, no-linealidad Sesión 3 (ML) / Sesión 4 (DL)

Y siempre: evaluar con métricas hidrológicas (NSE, KGE) además de RMSE/MAE — lo cerramos hoy en el notebook 04.

Resumen

  • ARIMA, ETS, Prophet, Pastas: cuatro filosofías — autoregresiva, suavizado recursivo, descomposición con changepoints, respuesta a impulsos (TFN).
  • Box-Jenkins: identificar (STL + ACF/PACF + tests) → estimar → diagnosticar residuos → pronosticar. Selección: AIC/BIC/AICc o rolling-origin CV.
  • Elegir según el problema: covariables → SARIMAX; sin covariables → ETS; sucio / festivos / changepoints → Prophet; piezometría irregular → Pastas/TFN.
  • Pronóstico ≠ un punto: comunicar intervalos (crecen con el horizonte). En producción: append + refit periódico.
